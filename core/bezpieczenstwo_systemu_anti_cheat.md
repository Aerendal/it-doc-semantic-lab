## Cel dokumentu

Zabezpieczyć system anti-cheat (AC) i jego dane przed obejściem, reverse engineeringiem i nadużyciami, przy zachowaniu prywatności użytkowników.


## Zakres i granice

- Obejmuje: architekturę AC (klient/serwer), integrację z grą/platformą, ochronę przed tamperem (code signing, integrity checks), wykrywanie (telemetria, heurystyki/ML), bezpieczeństwo komunikacji, aktualizacje AC, logowanie/audyt, prywatność.
- Nie obejmuje: polityki banów (osobny dokument) ani detali modeli wykrywających.

## Struktura sekcji (szkielet)

1. Architektura AC (komponenty klient/serwer, punkty integracji).
2. Ochrona klienta (integrity, anti-tamper, code signing, secure boot jeśli możliwe).
3. Komunikacja i bezpieczeństwo (mTLS, podpisy, obfuskacja krytycznych ścieżek).
4. Telemetria i wykrywanie (dane, sampling, anty-fraud, modele/heurystyki).
5. Aktualizacje i roll-out (wersjonowanie, kill-switch, rollback).
6. Logi/audyt i prywatność (co zbieramy, minimalizacja, zgody).
7. Incident response (fałszywe pozytywy, appeal process).
