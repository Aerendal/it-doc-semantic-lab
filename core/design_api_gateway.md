## Cel dokumentu

Zaprojektować API Gateway: routowanie, bezpieczeństwo, limity, observability i zarządzanie wersjami.



## Zakres i granice
Obejmuje: modele danych, endpointy/metody, kody błędów, authN/authZ, limity, wersjonowanie, polityki zgodności wstecznej, SLA. Nie obejmuje: szczegółów implementacji backendu ani UI.
## Użytkownicy i interesariusze
- **Backend Developer / API Owner** — projektuje i implementuje interfejs API
- **Frontend Developer / Consumer** — integruje się z API i zgłasza wymagania
- **Integration Architect** — definiuje standardy integracji i kontrakt API
- **QA Engineer** — weryfikuje kontrakty i scenariusze błędów

## Wejścia i wyjścia
- Wejścia: wymagania biznesowe, kontrakty domenowe, decyzje architektoniczne, NFR (wydajność, bezpieczeństwo), standardy org (naming, paginacja).
- Wyjścia: specyfikacja API (np. OpenAPI/AsyncAPI), przykładowe payloady, reguły wersjonowania, tabela kodów błędów, wymagania testów kontraktowych.

## Struktura sekcji (szkielet)

1. Routing i discovery (paths/hosts, service registry).
2. Bezpieczeństwo: authN (mTLS/OAuth), authZ (scopes/roles), WAF, rate limiting/throttling, JWT validation.
3. Transformacje: headers, payload shaping, versioning, fallback.
4. Observability: request ID, logi, metrics (latency/error), trace propagation.
5. Reliability: retries, circuit breaker, timeouts, canary/blue-green.
6. Zarządzanie API: quotas, plans, developer portal.
7. Operacje: config as code, tests, rollback.
