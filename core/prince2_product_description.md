# Product Description (PRINCE2 7)

## Cel dokumentu
Zdefiniować produkt projektu w kategoriach: celu, kompozycji, kryteriów jakości i metody weryfikacji — zgodnie z techniką Product-Based Planning PRINCE2 7. Product Description stanowi kontrakt między Project Managerem a Team Managerem: precyzuje co ma być dostarczone, jak zostanie sprawdzone i kto ponosi odpowiedzialność — eliminując ambiguity i konflikty jakościowe.

## Zakres i granice
Obejmuje: identyfikacja produktu (ID, nazwa, przeznaczenie), opis kompozycji (składowe), kryteria jakości (mierzalne parametry akceptacji), metoda weryfikacji (jak i przez kogo), tolerancje jakościowe, zależności od innych produktów, standardy i obowiązujące procesy.
Poza zakresem: szczegółowa specyfikacja techniczna (Software Requirements Spec), plan testów (Test Strategy).

## Wejścia i wyjścia
Wejścia: Project Product Description (nadrzędny, z Project Initiation), Work Package od Project Managera, standardy jakościowe organizacji, wymagania od Product Owner/Klienta.
Wyjścia: podpisana Product Description → podstawa Quality Review → odbiór produktu (Product Status Account).
