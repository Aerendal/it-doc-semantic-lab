# OPC UA Integration Requirements


## Metadane

- Właściciel: Backend Developer
- Wersja: v0.1
- Data aktualizacji: RRRR-MM-DD
- Status: draft | in review | approved

> Powiązania: linkage_index.jsonl


## Cel dokumentu

Określić wymagania integracji OPC UA między systemami OT/IT, zapewniając zgodność, bezpieczeństwo i niezawodność wymiany danych przemysłowych.


## Zakres i granice

- Obejmuje: namespace/AddressSpace, model danych i typy, profile/companion specs, discovery i endpoints, security profiles (sign/encrypt), user/token policies, subskrypcje i sampling, QoS i buffering, mapping do systemów IT (SCADA/MES/IoT/cloud), certyfikaty i rotacje, wydajność i SLA, testy zgodności, monitorowanie.
- Poza zakresem: projekt sprzętu i sieci OT (osobne), pełne bezpieczeństwo fizyczne OT.


## Użytkownicy i interesariusze
- **Backend Developer / API Owner** — projektuje i implementuje interfejs API
- **Frontend Developer / Consumer** — integruje się z API i zgłasza wymagania
- **Integration Architect** — definiuje standardy integracji i kontrakt API
- **QA Engineer** — weryfikuje kontrakty i scenariusze błędów

## Wejścia i wyjścia

- Wejścia: istniejące serwery/klienci OPC UA, modele danych, companion specs, polityki security, SLA/latency, topologia sieci, wymagania IT/OT, certyfikaty/PKI.
- Wyjścia: spec integracji (endpoints, security, namespace mapping), wymagania wydajności/SLA, polityki certów, plan testów zgodności, monitoring i alerty, runbook operacyjny.

- **Kryterium:** Informacje są poprawne merytorycznie i aktualne

- **Próg OK:** Przegląd co 3 mies.
- **Narzędzie:** regulation_updater.py

- **Kryterium:** Terminologia i struktura są spójne w całej bibliotece

- **Metryka:** Odsetek sekcji z wypełnionymi standards_refs
