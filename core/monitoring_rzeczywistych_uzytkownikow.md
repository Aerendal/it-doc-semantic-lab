# Monitoring rzeczywistych użytkowników (RUM)


## Metadane

- Właściciel: DevOps Engineer
- Wersja: v0.1
- Data aktualizacji: RRRR-MM-DD
- Status: draft | in review | approved



## Cel dokumentu

Mierzyć doświadczenie realnych użytkowników (RUM) w aplikacji/webie, by wykrywać problemy wydajnościowe i UX.



## Zakres i granice
- Obejmuje: KPI/SLO, metryki/logi/traces, źródła i agregację, alerty/reguły, dashboardy, runbooki i testy syntetyczne.
- Poza zakresem: implementacja funkcjonalna usług.
## Użytkownicy i interesariusze
- **DevOps / Platform Engineer** — zarządza infrastrukturą i pipeline'ami wdrożeniowymi
- **SRE (Site Reliability Engineer)** — definiuje SLO/SLI i zarządza niezawodnością
- **Development Team** — dostarcza artefakty do wdrożenia
- **Security Officer** — weryfikuje zgodność wdrożeń z polityką bezpieczeństwa

## Wejścia i wyjścia
- Wejścia: SLO/SLI, architektura usług, krytyczne ścieżki, limity budżetu zdarzeń, progi biznesowe.
- Wyjścia: katalog metryk/logów/traces, konfiguracja alertów, dashboardy, runbooki/eskalacje, plan przeglądów.

- Downstream: konsumpcja rezultatów (zespoły, usługi, dokumenty pokrewne).

## Fazy cyklu życia
- Definicja SLO/SLI i krytycznych ścieżek.
- Projekt metryk/logów/traces i alertów.
- Ustawienie dashboardów i testów syntetycznych.
- Przeglądy i tuning progów.
## Struktura sekcji (szkielet)

1. Zakres: platformy (web/mobile), krytyczne ścieżki (login, płatność, search).
2. Metryki: Core Web Vitals (LCP/FID/CLS), TTI, error rate, availability, wersje/urządzenia/regiony.
3. Instrumentacja: SDK/JS snippet, sample rate, privacy (PII masking), consent.
4. Dashboardy i alerty: progi SLA per region/urzadzenie, percentyle (p75/p95), heatmapy błędów.
5. Diagnostyka: session replay (zgoda), waterfall, API timing, correlation ID.
6. Raportowanie: trend, regresje po release, segmentacja, linki do backlogu.
