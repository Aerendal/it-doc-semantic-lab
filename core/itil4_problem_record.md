# Problem Record (ITIL 4)

## Cel dokumentu
Udokumentować zidentyfikowany Problem w zarządzaniu usługami IT zgodnie z praktyką Problem Management ITIL 4. Rekord obejmuje: identyfikację i kategoryzację problemu, analizę root cause (RCA), powiązane incydenty, Known Errors, tymczasowe workarounds i trwałe rozwiązanie — umożliwiając eliminację powtarzających się incydentów i obniżenie ryzyka operacyjnego.

## Zakres i granice
Obejmuje: dane identyfikacyjne problemu (ID, status, priorytet, właściciel), opis symptomu i wpływu na usługi, powiązane incydenty, analiza root cause (5 Why / Ishikawa), Known Error z workaroundem, plan trwałego rozwiązania, metryki recurrence.
Poza zakresem: Change Record dla wdrożenia rozwiązania (oddzielny artefakt ITSM), Incident Records (oddzielny formularz).

## Wejścia i wyjścia
Wejścia: Incident Records (powtarzające się incydenty), analiza trendów ITSM, alerty monitoringu, wyniki post-incident review.
Wyjścia: Problem Record z RCA, Known Error Database (KEDB) entry, Change Request (jeśli wymagana zmiana), metryki Problem Management.
